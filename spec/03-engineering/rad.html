Provider boundary

Cursor and Grok are workers, not architecture

Orchestration side

  • Owns product goal and capability frontier.
  • Writes capability contract.
  • Assembles canonical context.
  • Sets scope, repair limit and escalation rules.
  • Chooses provider based on capability needs.

Implementation side

  • Reads the bounded contract and context.
  • Builds inside an isolated worktree/branch.
  • May use subagents and local tools.
  • Cannot redefine architecture or acceptance.
  • Returns code plus evidence bundle.
Swap test: replacing Cursor/Grok with another capable provider should not require changing the capability contract, canonical agent role or verification semantics.
RAD cycle

One capability at a time

1

Select

Choose the smallest valuable reachable gap beyond VERIFIED state.

2

Delete / simplify

Challenge the requirement before adding architecture or infrastructure.

3

Contract

Freeze observable behaviour, scope, invariants and acceptance evidence.

4

Build

Implement one end-to-end vertical slice in isolation.

5

Verify

Independent deterministic evidence outranks model confidence.

6

Commit or learn

Update the ledger only with verified capability or reliable blocking evidence.

Capability quality

Build behaviour, not infrastructure

Good

“Moving a building gives immediate provisional feedback, then exact geometry verification and an updated setback result.”

Weak

“Build the geometry pipeline.”

The first can be observed and verified. The second invites unbounded architecture work without a clear truth condition.

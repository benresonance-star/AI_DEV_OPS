Patterns

Recurring rules for how Plasma owns world state, changes safely, scales computation, refines intelligently and develops itself through RAD.

Canonical registryPattern Book is the current visual projection
Pattern families

Five families

1

World

Authority, evidence, projections, stable identity, graphlets and multi-representation spatial state.

2

Change

Propose → validate → commit, dependency invalidation, typed operations and local failure containment.

3

Scale

Progressive world resolution, cheap-before-expensive tests and coarse reject / fine confirm.

4

Intelligence

Question-driven refinement, branching, capability frontier and human attention management.

5

Development / RAD

Capability contracts, smallest vertical slices, deterministic verification, bounded repair, frontier management and architecture escalation.

Reference rule

Patterns are not tasks

Architecture contracts, capabilities, agent roles, tests and ADRs reference pattern IDs. They do not rewrite the pattern as another specification.

Example traceability:

CAP-P012 → PATTERN-2.2 + PATTERN-3.1 → ARCH-DEPENDENCY-001 → TEST-TW-004

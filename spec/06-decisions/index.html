Architectural Decisions

Why foundational architecture changes, what evidence forced them, and how they update the canonical definitions without becoming a second copy of the system.

Canonical registryHuman gate for major changes
When required

Use an ADR for high-coupling decisions

World semantics

North-star invariants, primitives, graphlet identity/composition or revision semantics.

Authority + storage

Canonical storage, exact geometry authority or persistence strategy.

System boundaries

Public operation contracts, cross-language boundaries or security boundaries.

Major dependencies

Replacement of foundational engines or frameworks with migration impact.

Distributed execution

Introducing execution topology that materially changes failure, consistency or deployment semantics.

Irreversible migration

Any significant migration where rollback, compatibility or data loss is material.

Local and reversible implementation details normally do not require an ADR.

Authority rule

The ADR explains why; the owning spec defines what

After an ADR is accepted, update the actual canonical definition in its owning section. The ADR remains the rationale and historical decision record, not a parallel architecture definition.

Agents may propose ADRs. They may not unilaterally ratify constitutional or architectural changes that require the human architecture gate.

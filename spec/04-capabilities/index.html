Capabilities

The living definition of what Plasma can demonstrably do, what is being built now, and what sits immediately beyond the verified frontier.

CanonicalObservable behaviour
Unit of progress

Capabilities, not components

Good capability

Moving a building gives immediate provisional feedback, then exact geometry verification and an updated setback result.

Weak task

Build the geometry pipeline.

A capability must be observable in a real or synthetic test world and verifiable against explicit acceptance criteria.

Frontier

Select the smallest valuable reachable gap

The Selector chooses work immediately beyond VERIFIED state. It does not select a subsystem simply because the subsystem seems foundational or interesting.

Capability definitions reference patterns and architecture contracts by stable ID. They do not redefine either.
Initial frontier candidates

Smallest architectural feasibility sequence

CAP-P001

Site boundary world state

A site boundary imports into stable world identity with reproducible state.

CAP-P002

Envelope exact + display

A building envelope produces authoritative OCC BRep and a derived display mesh.

CAP-P003

Reproducible edit

A typed operation moves or resizes the envelope and records the change.

CAP-P004

Planning checks

Setback and height checks return explicit pass/fail evidence.

CAP-P005

Revision restore

The previous world state can be restored exactly after an accepted edit.

CAP-P006

Selective invalidation

Only affected derived results become dirty after a local change.

CAP-P007

Typed language proposal

A natural-language instruction can propose one bounded typed operation without directly mutating canonical state.

These remain candidate entries until each has a formal capability contract and verification evidence.
